# e-hentai.org Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search, browse and download e-hentai.org galleries (whole albums and single pictures) in R34 Downloader,
using the same grid, viewer, slideshow, favorites and downloads as rule34.xxx.

**Architecture:** Add a small site layer (`src/r34dl/sites/`).
- The search tab talks to a `Site` object instead of calling `api.ApiClient` directly.
- rule34.xxx becomes a thin wrapper around today's `api.py`.
- e-hentai is split in two: `sites/ehentai.py` holds pure parsers and query builders, and `sites/ehclient.py`
  holds the paced Qt client, the resolver and the download feeder.
- A gallery opens in a `GalleryTab`, which is a `SearchTab` fed by the gallery's pages.
- e-hentai page posts get their file address lazily, through `win.resolve(post, cb)`.

**Tech Stack:** Python ≥ 3.10, PySide6 (QtNetwork for all HTTP), pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-22-e-hentai-design.md`

## Global Constraints

- No new dependencies. Parse HTML with `html.parser` or small regexes. All HTTP goes through QtNetwork, and
  every request is built with `api.request()` (User-Agent, 20 s timeout).
- rule34.xxx behaviour, files and config keys stay unchanged. `history.txt`, `favorites.json` and the
  top-level `user_id`, `api_key`, `template`, `exclude`, `blacklist`, `followed` and `saved_searches` keep
  their meaning. All existing tests keep passing unmodified, except where a task says to change one.
- e-hentai data lives in its own files and config section: `history-e-hentai.txt`, `favorites-e-hentai.json`
  and `cfg["sites"]["e-hentai"]`.
- e-hentai pacing for the API, HTML pages and full-size images: one request at a time, at least `EH_GAP_MS =
  1000` apart, a pause of `EH_BURST_PAUSE_MS = 5000` after every `EH_BURST = 4` requests, and a backoff on
  429/503 using `api.RETRY_DELAYS_MS`. Thumbnails from the thumbnail CDN use the existing `MAX_THUMBS` queue.
- Scraped links to search, gallery and picture pages must be `https://e-hentai.org/...`. Image addresses may be
  http or https on any host, but are refused for loopback, private and link-local IPs and `localhost`.
- The cookies `ipb_member_id` and `ipb_pass_hash` must never appear in logs, errors, file names or URLs.
  `api.scrub()` masks them.
- Downloads save the original (`fullimg.php`) when the e-hentai login is set and the page offers it; otherwise
  they save the resized `<img id="img">` copy. Viewing and the slideshow always use the resized copy.
- Large-download warning: more than `EH_WARN_PICTURES = 200` e-hentai pictures in one batch asks first.
- Default e-hentai filename template: `ehentai_{album_id}_{page}`.
- e-hentai ids: a gallery post has `id = gid * 100000`, and a page post has `id = gid * 100000 + page`
  (1-based). Ids are unique within the site, so per-site sets and dicts keyed by `post.id` keep working.

## Review Focus

1. **Image limit hit in the middle of an album download:** the queue pauses, the files already saved stay, the
   user gets one clear message, nothing retries in a loop, and a half-done ZIP keeps its parts. Test:
   Task 8, `test_feeder_pauses_on_509`.
2. **A gallery whose page has no "Download original" link, while logged in:** it falls back to the resized
   copy and the download does not fail. Test: Task 4, `test_parse_picture_without_original`.
3. **A content-warning page instead of the gallery** (flagged galleries): the request always carries
   `nw=always`, and a page that still turns out to be the warning reports "content warning" instead of "empty
   gallery". Test: Task 4, `test_parse_gallery_content_warning`.
4. **Upgrading with existing rule34 data and an old config file that has no `sites` key:** everything loads,
   nothing is rewritten, and e-hentai gets its defaults. Test: Task 1, `test_old_config_gets_site_defaults`.
5. **Tags with spaces and quotes typed into the e-hentai boxes** (`female:big breasts`, `"x"`, `-language:english`):
   the query quotes them correctly and never breaks the URL. Test: Task 4, `test_build_query_quotes_spaces`.

**Interfaces:**
- Produces:
  - `EH = "https://e-hentai.org"` and `EH_API = "https://api.e-hentai.org/api.php"`.
  - `NAMESPACE_KINDS: dict[str, str]`, the mapping from the spec. An unknown namespace → `"general"`, and so
    does a tag with no namespace.
  - `split_tags(text) -> list[str]`: lines or commas; spaces are kept inside a tag; stripped; empty entries
    dropped.
  - `build_query(include, exclude, blacklist) -> str`:
    - Each tag becomes `ns:"tag$"`, or `"tag$"` without a namespace.
    - Excludes become `-ns:"tag$"`; a leading `-` in include also means exclude.
    - Any `"` inside a tag is removed.
    - The result is joined with spaces.
  - `search_url(query, cursor: int | None) -> str` builds
    `https://e-hentai.org/?f_search=<urlencoded>&inline_set=dm_l&nw=always`, plus `&next=<cursor>`.
  - `parse_search(html: str) -> tuple[list[tuple[int, str]], int | None]` returns `(gid, token)` pairs in page
    order, without duplicates, and the next cursor from the `next=` link (`None` when there isn't one).
  - `gdata_body(pairs) -> bytes` builds the JSON body, at most 25 pairs, with `namespace: 1`.
  - `parse_gdata(body: bytes) -> list[Post]` returns gallery posts:
    - `id = gid * 100000`, `kind="gallery"`, `page_url = f"{EH}/g/{gid}/{token}/"`
    - `preview_url` = the https thumb
    - `tags` = the namespaced strings
    - `tag_info` = `{tag: (NAMESPACE_KINDS[ns], 0)}`
    - `rating` = the category, lowercased
    - `score` = `int(float(rating) * 10)`
    - `album = {gid, token, title, pages: int(filecount), category}`
    - `error` entries and any entry with a non-https thumb are skipped.
  - `gallery_url(gid, token, p) -> str` is `f"{EH}/g/{gid}/{token}/?p={p}&nw=always"`.
  - `parse_gallery(html: str, gallery: Post) -> tuple[list[Post], int | None]` returns the page posts and the
    next `p`, or `None`:
    - Each page post has `id = gid * 100000 + n`, `kind="page"`, `page_url` = the `/s/` link (kept only if
      it starts with `EH + "/s/"`), and `file_name` from the thumb's `title` (`"Page 4: 004.jpg"`).
    - `preview_url` is the sprite URL, and the crop goes in `album["sprite"] = (x, y, w, h)` when the thumb is
      a background sprite.
    - Tags and `tag_info` are copied from the gallery.
    - `album = {**gallery.album, "page": n}`.
  - `GalleryWarning(Exception)` is raised when the HTML is the content-warning page.
  - `parse_picture(html: str) -> tuple[str, str | None]` returns `(shown_url, original_url)`. The original is
    the `fullimg.php` link, or `None` when absent. Raises `ImageLimit` when the shown src ends in `/509.gif`,
    and `ValueError` when there is no `img#img`.
  - `safe_image_url(url: str) -> bool`: http(s) only; `False` for `localhost` and for loopback, private,
    link-local and reserved IP literals (`ipaddress`).
  - `ImageLimit(Exception)`.

### Task 5: The paced e-hentai client and the e-hentai Site

**Files:**
- Create: `src/r34dl/sites/ehclient.py`
- Modify: `src/r34dl/sites/__init__.py` (register it), `src/r34dl/api.py` (`scrub` masks
  `ipb_member_id=`/`ipb_pass_hash=` values)

**Interfaces:**
- Consumes: the Task 4 functions; `Site` from Task 2; `config.site_cfg`.
- Produces:
  - `class EhQueue(QObject)` runs jobs one at a time with the pacing from Global Constraints:
    - `get(url, cb)` and `post(url, body, cb)`, where `cb(status: int | None, body: bytes, error: str)`.
    - It adds the `Cookie: ipb_member_id=…; ipb_pass_hash=…; nw=1` header when a login is set
      (`set_login(member_id, pass_hash)`).
    - Retries on 429/503 with `RETRY_DELAYS_MS`.
    - `clear()` drops pending jobs.
  - `class EhentaiSite(Site)`, `name="e-hentai"`, `page_jump=False`:
    - `fetch(query, cursor, gen, cfg)` loads the search page, then `gdata` in chunks of 25, then emits
      `page_ready(gen, galleries, next_cursor)`.
    - `fetch_gallery(gallery: Post, p: int | None, gen)` emits the same `page_ready` with page posts and the
      next `p`. A `GalleryWarning` becomes `failed(gen, "This gallery is behind a content warning that the
      app couldn't skip.")`.
    - `resolve(post, for_download, cb)`:
      - Page posts only. Loads `post.page_url` and parses it.
      - Sets `post.file_url` to the shown URL, or, when `for_download` and logged in and the original exists,
        to the original.
      - Caches the shown URL in `post.album["shown"]` so viewing twice costs one request.
      - Rejects a URL that fails `safe_image_url`.
      - An `ImageLimit` becomes `cb(post, "IMAGE_LIMIT")`.
    - `suggest_request` returns `None`. Autocomplete is out of scope, and the box shows no suggestions.
    - `post_page_url(post)` returns `post.page_url`.

  - `class EhDownloadFeeder(QObject)`, `__init__(site: EhentaiSite, downloader: Downloader)`:
    - `add(jobs: list[tuple[Post, Path]])` and `cancel()`.
    - It resolves one post at a time, through the site queue so the pacing applies, then hands it to the

      complete.

    - Before queueing, if the e-hentai picture count is more than `EH_WARN_PICTURES`, it asks: "Download N
      pictures from e-hentai? This uses your image limit (originals use more) and takes about M minutes at a
      polite pace." M is `N × (2 × EH_GAP_MS) / 60000`, rounded up.
    - ZIP and folder albums work unchanged, because targets are known before resolving.
  - On `paused`, the status bar shows the message and a "Resume e-hentai downloads" action appears in the
    progress area. History marks use `config.add_history(post.id, "e-hentai")`.
